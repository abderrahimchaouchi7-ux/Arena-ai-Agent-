# Data sources, provenance and licensing

Every piece of religious content in this app comes from a named, versioned
upstream source. Nothing is generated by a language model, and nothing is
attributed to a scholar or collection without a citation the reader can check.

The build pipeline is `scripts/build-data.mjs` (fetch → transform → emit) and
`scripts/verify-data.mjs` (13 release-gating assertions). Both run against a
local cache in `.data-cache/` so a build never needs the network.

## 1. Quran

| Aspect | Value |
| --- | --- |
| Arabic script | Tanzil — **Uthmani** script |
| Recitation basis | **Hafs ʿan ʿAsim** |

| Surahs / verses | **114 / 6,236** |
| Search script | Tanzil **simple-clean** (unvowelled), 1:1 aligned with Uthmani |
| Mushaf indexes | 30 juz · 60 hizb · 604 pages · 15 sajda |
| English translation | Saheeh International (via QuranEnc, `english_saheeh`) |
| French translation | Muhammad Hamidullah (via QuranEnc, `french_hameedullah`) |
| Upstream | [`risan/quran-json@6523a9a`](https://github.com/risan/quran-json) |
| Licence | **CC BY-SA 4.0** — attribution and share-alike required; see `LICENSE` |

### Notes that affect rendering

- **The Basmala is embedded in verse 1** of all 113 surahs that have one
  (At-Tawbah has none). The reader therefore does **not** print a second
  Basmala above the verse — it only annotates that the opening phrase is part
  of verse 1. This is asserted in `src/data/data.test.ts`.
- Surahs **95 and 97** spell the Basmala with a shadda on the ba (`بِّسْمِ`).
  Any prefix check must normalise diacritics first.
- **42:2** (`عٓسٓقٓ`) carries maddah marks (U+0653) rather than harakat. That
  is correct text, not missing vocalisation.
- Tanzil's `indexes.hizbs` contains **240 quarter-hizb** entries. The 60 hizb
  are derived by taking every fourth; both are kept in `quran-meta.json`.

## 2. Adhkar and Du'a

### Hisn al-Muslim (fortress of the Muslim)

- Upstream: [`YousefAsalya/Islamic-Pro-azkar-API@d793023`](https://github.com/YousefAsalya/Islamic-Pro-azkar-API)
- Licence: **MIT**
- Contents: **132 chapters / 267 items**, Arabic + English, aligned by chapter
  id then array index.
- `transliteration` is `null` for most items upstream, so the app shows a
  transliteration field only where the source actually provides one.

### Morning and evening adhkar

- Upstream: [`Seen-Arabic/Morning-And-Evening-Adhkar-DB@29d7623`](https://github.com/Seen-Arabic/Morning-And-Evening-Adhkar-DB)
- Licence: **MIT**
- Contents: **34 items** with `count`, `fadl` (virtue) and a `source` field
  carrying a real hadith reference and grading, e.g.
  `أبو داود، برقم 3667، وحسنه الألباني، في صحيح أبي داود`.

### Honest limitation: no French adhkar translation

A search of public datasets found **no French translation** of Hisn al-Muslim
under a permissive licence. Rather than machine-translate religious text — which
would risk altering its meaning — the app shows Arabic and English and states
plainly that no French translation is available for this source. This is a
deliberate omission, not a bug.

### Source references and grading

The Hisn al-Muslim dataset cites the **Hisn chapter**, not an individual hadith
number, for most items. The app therefore attributes those items to the Hisn
chapter and does **not** invent a hadith reference or an authenticity grade.
Where the morning/evening source supplies a real reference with a grading, it is
displayed verbatim with its grading authority named (e.g. al-Albani).

## 3. Hadith

- Upstream: [`AbdullahNaseer01/hadith-books-data@c4e5e55`](https://github.com/AbdullahNaseer01/hadith-books-data)
- Bundled offline: **6 collections / 1,844 hadiths** (~300 per collection) to
  keep the initial download small. Full collections can be fetched on demand
  and cached in IndexedDB when `VITE_HADITH_FULL_BASE_URL` is configured.

| Collection | Compiler | Total | Offline |
| --- | --- | --- | --- |
| Sahih al-Bukhari | al-Bukhari (d. 256 AH) | 7,433 | 305 |
| Sahih Muslim | Muslim (d. 261 AH) | 7,561 | 310 |
| Sunan Abi Dawud | Abu Dawud (d. 275 AH) | 5,274 | 315 |
| Jami' at-Tirmidhi | at-Tirmidhi (d. 279 AH) | 3,956 | 314 |
| Sunan an-Nasa'i | an-Nasa'i (d. 303 AH) | 5,700 | 300 |
| Sunan Ibn Majah | Ibn Majah (d. 273 AH) | 4,341 | 310 |

### Grading policy — read this before displaying grades

The upstream README states that its `status` field is **not accurately
represented**. This project therefore **never surfaces that field**. Instead:

- **Sahih al-Bukhari** and **Sahih Muslim** are shown as accepted-authentic at
  the *collection* level, which is the mainstream scholarly position and does
  not depend on the unreliable per-hadith field.
- The **four Sunan** are shown **without an asserted grade**, with an explicit
  note in the UI and in `hadith-index.json` recording the upstream warning.
- No grading is ever invented, inferred, or copied from a field the source
  itself flags as unreliable.

### Data quirks handled explicitly

- `chapterId` in the upstream data holds the **chapter number as a string**, and
  is unrelated to `chapters[].id`. The correct join key is `chapterNumber`.
  (Bukhari coincidentally has both equal, which masks the bug.)
- `hadithNumber` can be a **grouped span** such as `"299, 300, 301"`. It is kept
  as a label and never passed to `Number()`.
- `hadithEnglish` is sometimes the literal `"As above."`, modelled as
  `textRepeatsPrevious: true` so the UI renders a notice instead of that string.
- Sahih Muslim opens with an unnumbered Muqaddimah (`hadithNumber "0"`), so the
  numbering invariant is `>= 0`, not `>= 1`.

## 4. Adhan audio — licensing position

**No adhan recording is bundled, copied or redistributed.**

A review of the available muezzin recordings found **no source with a licence
permitting redistribution**. Bundling them would infringe the reciters' and
recorders' rights. Instead:

1. `src/lib/audio.ts` ships a **catalogue of named muezzins** with the remote
   URLs they are publicly available at, resolved from an optional
   `VITE_ADHAN_BASE_URL`.
2. Every URL is **probed at runtime**. If it cannot be reached, the UI shows an
   honest "source unavailable" state with the reason — it never fakes playback
   and never shows a playing bar for audio that is not there.
3. Users can **import their own audio file** from local storage, which is stored
   in IndexedDB and played back offline. That file is the user's own
   responsibility.
4. The "short tone" notification option is a **synthesised Web Audio tone**, so
   it needs no recording at all.

If you obtain written permission to redistribute a specific recording, add it to
the catalogue with the permission documented alongside it.

```
hadith          AbdullahNaseer01/hadith-books-data@c4e5e554fc7bd498c8f3e0fac9e627b3d5a2e387
```

`npm run data:verify` runs **13 assertions** that gate a release, including:
114 surahs, exactly 6,236 verses, tashkeel on every verse, 1:1 Uthmani↔simple
alignment, complete EN and FR translations, 30 juz / 60 hizb / 604 pages, a
source reference on every adhkar item, no hadith lacking Arabic/English/number,
the grading disclaimer being recorded, and all four upstream commits pinned.

Current result: **13/13 PASS**.
